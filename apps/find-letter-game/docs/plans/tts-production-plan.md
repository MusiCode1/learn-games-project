## 1. ‏היקף

‏26 אותיות × 11 ניקודים (פתח קיים) = ‏**286 צירופים פוטנציאליים**.

‏פחות שיתופים צפויים ‏(מ-סיבוב 1):

| ‏שיתוף | ‏בסיס |
|--------|--------|
| ‏ס + שׂ | ‏אותו צליל בעברית מודרנית |
| ‏ט + ת | ‏אוחדו בסיבוב 1 |
| ‏כּ + ק | ‏אוחדו בסיבוב 1 (תלוי בניקוד) |
| ‏ו + ב רפה | ‏אותו צליל (שני "v") |
| ‏ח + כ רפה | ‏אותו צליל ("kh") |
| ‏א + ע | ‏שתיהן אילמות במודרנית |

‏אומדן ‏unique MP3 ‏אחרי שיתופים: ‏**~210-220 קבצים**.

‏בעיות צפויות (לפי סיבוב 1):

‏- ‏פ רפה — ‏Sarah מתעלמת מ-`ָ`/`ַ` — ‏תעתיק לטיני
‏- ‏צ — ‏אולי דורש ‏`[Israeli accent]`
‏- ‏ר — ‏American R, ‏לא נפתר, ‏פשרה ידועה
‏- ‏ז — ‏בסיבוב 1 דרש `זַה` במקום `זָא`
‏- ‏ח, ‏ט — ‏בסיבוב 1 בלעו את הסיומת
‏- ‏**עיצור** — ‏הבעיה החדשה: ‏הברה ‏(`be`) ‏במקום עיצור טהור
‏- ‏**גרוניות + עיצור** — ‏לא נסגרו בסיבוב 1; ‏אולי לעולם לא יהיה פתרון tts

## 2. ‏האתגר המרכזי

‏הבעיה הקשה ביותר: ‏**איך להפיק עיצור טהור**.

‏אם נמצא פתרון לעיצור — ‏שאר הניקודים פשוטים יחסית (יש להם תנועה).

‏אם לא — ‏הצירופים של ‏`vowel: none` ‏יישארו Web Speech fallback ‏לתמיד (לא רצוי, אבל קביל).

‏השאר ‏(`shva` ‏וכל הניקודים האחרים) ‏הוא ‏extension של מה שעבד בסיבוב 1, ‏כנראה שיעבוד טוב.

## 3. ‏שלבי התכנית

### Stage A — ‏מחקר (1-2 שעות עבודת תכן, ‏ידני בעיקר)

‏מטרה: ‏למצוא **שיטה אחת** ‏שעובדת לעיצור. ‏אחרי שיש שיטה — ‏Stage B ו-C ‏הם batch מכני.

**‏טכניקות לבדוק (לפי סדר עדיפות):**

‏1. **‏עריכה ידנית של MP3 — ‏cut at-source**
   ‏- ‏ייצור הברה רגילה ‏(`'בְּ'` ‏או ‏`'בָּא'` או 'בַ').
   ‏- ‏פיצול האודיו ל-2 חלקים ב-ffmpeg: ‏עיצור (50-100ms ראשונים) + ‏תנועה.
   ‏- ‏שמירה רק של החלק העיצורי.
   ‏- ‏סיכוי הצלחה: ‏גבוה ‏אם ניתן לזהות את ה-boundary עם תקינות.
   ‏- ‏בעיה: ‏auto-detection של ‏boundary יכול לדרוש ML/heuristic; ‏ידני יקח שעות.
   ‏- ‏Tool: ‏ffmpeg ‏+ ‏Python ‏עם librosa או pyAudioAnalysis ‏לdetection.

‏2. **‏Voice אחר ב-ElevenLabs**
   ‏- ‏בסיבוב 1 השתמשו ב-Sarah. ‏יש voices אחרים שאולי טוב יותר לעברית.
   ‏- ‏אצל ‏ElevenLabs (לפי `/v1/voices`) ‏אין voice עברי native. ‏רוב הvoices ‏הם multilingual. ‏אולי Antoni או Adam מטפלים בעברית שונה.
   ‏- ‏סיכוי הצלחה: ‏בינוני. ‏הבעיה הבסיסית של "הברה במקום עיצור" ‏היא של ‏מודל ה-TTS, ‏לא של ה-voice.

‏3. **‏מודל אחר ב-ElevenLabs**
   ‏- ‏`eleven_multilingual_v2`, ‏`eleven_turbo_v2_5` — ‏אופציות. ‏אולי הם עושים phoneme-level יותר טוב.
   ‏- ‏סיכוי הצלחה: ‏בינוני.

‏4. **‏Azure he-IL-AvriNeural** ‏(הקול ש-kriale משתמש)
   ‏- ‏זה הקול ש-kriale.co.il/vowels-generator/ ‏משתמש דרך colbass.com. ‏אם kriale ‏נשמע טוב — ‏הקול הזה יודע משהו שSarah לא.
   ‏- ‏Azure TTS Free tier: ‏500K characters/month, ‏מספיק לבדיקה.
   ‏- ‏צריך לבדוק אם AAC proxy תומך, ‏אחרת ‏ייצור ישיר.

‏5. **‏ספק אחר — Google Cloud TTS**
   ‏- ‏יש קולות עבריים native (he-IL-Wavenet-A, ‏he-IL-Wavenet-B, ‏he-IL-Wavenet-C, ‏he-IL-Wavenet-D).
   ‏- ‏SSML ‏מאפשר control יותר טוב על phonemes.

‏6. **‏Audio tags ‏(לא נוסה בעיצור)**
   ‏- ‏`[short]`, ‏`[whisper]`, ‏`[fast]` ‏— ‏אולי יחתכו את התנועה הטבעית.
   ‏- ‏סיכוי הצלחה: ‏נמוך אבל שווה ניסוי מהיר.

**‏תוצר Stage A:** ‏החלטה על שיטה (אחת או hybrid) + ‏proof על 3-5 אותיות.

### Stage B — ‏Bulk production (2-3 שעות עבודה מכנית)

‏אחרי שיש שיטה, ‏ייצור ‏~210-220 קבצים בbatch.

**‏אוטומציה:**

```bash
# pseudocode
for letter in ALL_LETTERS:
    for vowel in ALL_VOWELS:
        if not is_shared(letter, vowel):  # מבדיל את ‏shared MP3
            speak = compute_speak(letter, vowel)
            mp3 = synthesize(speak, method=chosen_method)
            save(f"tts-review/{filename(letter, vowel)}.mp3", mp3)
```

‏הסקריפט צריך לכלול:
‏- ‏Mapping ‏שיתופים (סייט הראשי: ‏אם ‏letterA+vowel ‏ו-letterB+vowel ‏צליל זהה — ‏מייצרים פעם אחת).
‏- ‏Rate limit handling (Sarah: ‏10K characters/דקה).
‏- ‏Resume from interruption.

**‏תוצר Stage B:** ‏~210 ‏קבצי MP3 ב-`tts-review/batch-<timestamp>/`.

### Stage C — ‏Quality control (1-2 שעות, ‏רובו אוטומטי)

‏Gemini judge פר קובץ:

```python
for mp3 in batch:
    expected = compute_expected_sound(letter, vowel)  # 'b with hirik' = 'bee'
    transcription = gemini_transcribe(mp3)
    if not matches(transcription, expected):
        flag_for_manual_review(mp3)
```

‏Categories:
‏- ‏✅ ‏תקין (~90%?)
‏- ‏⚠️ ‏על הגבול — ‏צריך האזנה ידנית
‏- ‏❌ ‏שגוי — ‏variant אחר

‏Manual review רק על flagged. ‏סביר 10-20 קבצים בלבד.

**‏תוצר Stage C:** ‏batch ‏מאומת, ‏עם רשימת variants לקבצים בעייתיים.

### Stage D — ‏Upload + Integration (30 דק')

‏- ‏העלאת כל הקבצים ל-`tzlev-static/shared/tts/find-letter/` ‏דרך ‏`wrangler r2 object put`.
‏- ‏עדכון `TTS_FILES` ‏ב-`src/lib/utils/letters.ts` ‏עם ‏~210 entries חדשים. ‏אוטומטי מהsubmit.
‏- ‏עדכון test #22 ‏לכלול את כל הצירופים החדשים (להסיר את הפילטר ‏`PAIRS_WITH_MP3`).

### Stage E — ‏Verification (30 דק')

‏- ‏Build + preview
‏- ‏בדפדפן: ‏בחירת ניקוד מכל סוג, ‏האזנה ל-3-5 אותיות לכל ניקוד.
‏- ‏מספיק לוודא שhappy path עובד, לא לעבור על 210 קבצים ידנית.

## 5. ‏סדר ביצוע מומלץ

‏- ‏**Stage A קודם, ‏על עיצור בלבד**. ‏זה ה-bottleneck. ‏אם נכשל, ‏מחליטים אם:
  ‏- ‏לוותר על עיצור (Web Speech) ‏ולעבור לשאר הניקודים.
  ‏- ‏לחקור עוד טכניקות.
‏- ‏אחרי שיש שיטה לעיצור (או החלטה לוותר), ‏מתחילים מ-**הניקוד הפדגוגית הכי שימושי** ‏ולא מהכל בבת אחת:
  ‏1. ‏חיריק (תנועה נפוצה ב-CVC)
  ‏2. ‏סגול, ‏חולם, ‏שורוק
  ‏3. ‏צירה, ‏שווא
  ‏4. ‏קמץ ‏(זהה צלילית לפתח — ‏יכול לחלוק MP3, ‏אז זול)
  ‏5. ‏קובוץ, ‏חטפים, ‏(עיצור אם נמצא פתרון)
‏- ‏Stage B ‏יכול לרוץ באופן מצטבר — ‏ניקוד אחר ניקוד, ‏לא חייב הכל בבת אחת.

‏- ‏Azure: ‏500K characters/month free. ‏מספיק בקלות.
‏- ‏Google: ‏4M characters/month free for Wavenet. ‏הכי נדיב.

‏**‏המלצה:** ‏אם Sarah/eleven_v3 לא טוב לעיצור — ‏לשקול Azure (כי kriale משתמש בו ונשמע טוב).
