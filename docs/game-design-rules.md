# כללי עיצוב למשחקים לימודיים

מסמך זה מתאר את הכללים והעקרונות הבסיסיים שחלים על **כל** המשחקים הלימודיים בפרויקט. הכללים האלה נועדו להבטיח חוויית למידה עקבית, נגישה ואפקטיבית עבור תלמידים עם צרכים מיוחדים.

---

## 1. מערכת מחזקים (Booster/Rewards)

### מה זה ולמה זה חשוב

מחזקים הם תגמולים שהתלמיד מקבל אחרי מספר מסוים של הצלחות. המטרה היא לשמור על מוטיבציה ולחזק התנהגות למידה חיובית. במקום לתת תגמול אחרי כל תשובה נכונה (מה שעלול להפוך למשעמם), המערכת צוברת הצלחות ונותנת תגמול משמעותי יותר אחרי כמה הצלחות.

### איך זה עובד

1. **מונה הצלחות** — המערכת סופרת כמה תשובות נכונות התלמיד ענה מאז התגמול האחרון
2. **סף לתגמול** — כשהמונה מגיע למספר מוגדר (למשל 3 הצלחות), מופעל תגמול
3. **סוגי תגמול** — סרטון קצר, משחק חיצוני, או אתר אינטראקטיבי
4. **איפוס** — אחרי התגמול, המונה מתאפס והתלמיד ממשיך לצבור הצלחות

### מה צריך לממש

| רכיב | תיאור |
|------|--------|
| `boosterEnabled` | הגדרה (boolean) שמאפשרת למורה לכבות/להדליק את מערכת המחזקים |
| `turnsPerReward` | מספר ההצלחות הנדרשות לפני תגמול (מוגדר בהגדרות ה-booster) |
| `winsSinceLastReward` | מונה פנימי שעוקב אחרי מספר ההצלחות מאז התגמול האחרון |
| `ProgressWidget` | רכיב UI שמציג לתלמיד את ההתקדמות לתגמול הבא (למשל "2/3 לפרס") |
| `BoosterContainer` | רכיב overlay שמציג את התגמול (סרטון/אתר) כשמגיע הזמן |
| `triggerReward()` | פונקציה שמפעילה את התגמול כשהמונה מגיע לסף |

### אינטגרציה

כל המשחקים משתמשים בחבילה `learn-booster-kit` שמספקת את התשתית. הזרימה:

```
תשובה נכונה
  → winsSinceLastReward++
  → בדיקה: האם winsSinceLastReward >= turnsPerReward?
    → כן: triggerReward() → הצגת תגמול → איפוס מונה
    → לא: המשך למשימה הבאה
```

## 2. נעילת הגדרות (AdminGate)

### מה זה ולמה זה חשוב

תלמידים עם מוגבלות שכלית התפתחותית עלולים ללחוץ על כפתורים בטעות או מסקרנות, ולשנות הגדרות בלי להבין את המשמעות. נעילת ההגדרות מונעת מצב שבו התלמיד משנה את רמת הקושי, מכבה את המחזקים, או משנה הגדרות אחרות שהמורה קבע.

### איך זה עובד

הנעילה **אינה מבוססת על סיסמה רגילה** (שתלמיד יכול לנחש או לזכור). במקום זאת, היא מבוססת על **דפוס מורכב** שדורש הבנה קוגניטיבית שבדרך כלל תלמידים עם מוגבלות שכלית יתקשו לעקוב אחריו.

דוגמאות לדפוסים:
- לחיצה על רצף ספציפי של אלמנטים (למשל: פינה שמאלית-עליונה → פינה ימנית-תחתונה → מרכז)
- החזקה ארוכה של כפתור למספר שניות מסוים
- לחיצה על אזור "נסתר" במסך מספר פעמים

### מה צריך לממש

| רכיב | תיאור |
|------|--------|
| `AdminGate` | רכיב שעוטף את כפתור ההגדרות ומציג את הדפוס הנדרש |
| דפוס כניסה | מנגנון שמזהה את הדפוס הנכון ופותח את ההגדרות |
| timeout | אם הדפוס לא הושלם תוך זמן מסוים, המנגנון מתאפס |

### הערה חשובה

המטרה היא **לא** ליצור אבטחה הרמטית (תלמיד נחוש יוכל לפצח את הדפוס), אלא ליצור מחסום שמונע שינויים בטעות או מסקרנות רגעית.

## 3. צלילים ומשוב קולי

### מה זה ולמה זה חשוב

משוב קולי מיידי הוא קריטי ללמידה. תלמיד צריך לדעת מיד אם הצליח או טעה, והצליל מספק את המשוב הזה בצורה ברורה ואינטואיטיבית — גם אם התלמיד לא מסתכל על המסך באותו רגע.

### סוגי צלילים נדרשים

| צליל | מתי מתנגן | תיאור |
|------|-----------|--------|
| `playSuccess()` | תשובה נכונה | צליל חיובי, משמח, קצר |
| `playError()` | תשובה שגויה | צליל שלילי, לא מפחיד, קצר |
| `playWin()` | לפני תגמול (אופציונלי) | צליל חגיגי יותר |

### כללים טכניים

1. **קבצים אמיתיים בלבד** — חל איסור מוחלט להשתמש ב-Oscillators או צלילים מסונתזים. יש להשתמש בקבצי MP3 או WAV
2. **מיקום הקבצים** — קבצי הצלילים נמצאים בתיקיית `static/sounds` או מיובאים כ-assets
3. **ניהול מרכזי** — לוגיקת הצלילים מרוכזת בקובץ `sound.ts` ולא מפוזרת בקומפוננטות

### דוגמת קוד טיפוסית

```typescript
// src/lib/utils/sound.ts
import successSound from '$lib/assets/sounds/success.mp3';
import errorSound from '$lib/assets/sounds/error.wav';

export function playSuccess(): void {
  const audio = new Audio(successSound);
  audio.play().catch(e => console.warn('Audio play failed:', e));
}

export function playError(): void {
  const audio = new Audio(errorSound);
  audio.play().catch(e => console.warn('Audio play failed:', e));
}
```

## 4. השהייה במקרה של טעות (Cooldown)

### מה זה ולמה זה חשוב

כשתלמיד טועה, יש סכנה שהוא יתחיל ללחוץ אקראית על כל האפשרויות עד שימצא את התשובה הנכונה. זו לא למידה — זה ניחוש. מנגנון ההשהייה מונע את זה על ידי חסימת הקלט למספר שניות אחרי טעות, מה שמאלץ את התלמיד לעצור, לחשוב, ולנסות שוב בצורה מושכלת.

### איך זה עובד

1. **זיהוי טעות** — התלמיד בוחר תשובה שגויה
2. **משוב** — מושמע צליל שגיאה + מוצגת אנימציה (רעידה, הבהוב אדום)
3. **חסימה** — כל הכפתורים/אפשרויות נחסמים למשך זמן מוגדר
4. **חזרה** — אחרי ההשהייה, התלמיד יכול לנסות שוב **את אותה שאלה**

### נקודה קריטית

התלמיד **נשאר על אותה שאלה** אחרי טעות. אין מעבר לשאלה הבאה עד שהתלמיד עונה נכון. זה מבטיח שהתלמיד לא יכול "לדלג" על שאלות קשות.

### מה צריך לממש

| הגדרה | תיאור | ברירת מחדל טיפוסית |
|-------|--------|---------------------|
| `cooldownMs` | משך ההשהייה במילישניות | 2000-10000 |
| `resetCooldownOnTap` | האם לחיצה נוספת במהלך ההשהייה מאפסת את הטיימר | false |
| `maxWrongAttempts` | מספר טעויות מקסימלי לפני התערבות (אופציונלי) | 2-3 |

### משוב ויזואלי

בנוסף לצליל, יש להציג משוב ויזואלי ברור:
- **אנימציית רעידה (shake)** — על האלמנט שנלחץ בטעות
- **שינוי צבע** — הבהוב אדום או גבול אדום
- **חיווי השהייה** — אפשר להציג טיימר או אינדיקציה שהמערכת "חושבת"

## 5. הקראה (TTS — Text to Speech)

### מה זה ולמה זה חשוב

הרבה תלמידים עם צרכים מיוחדים מתקשים בקריאה או עדיין לא יודעים לקרוא. הקראה מאפשרת להם להשתתף במשחק ולהבין את ההוראות בלי להסתמך על טקסט כתוב.

### מתי מקריאים

- **תחילת סיבוב** — הקראת ההוראה או השאלה (למשל "איפה האות בּ?")
- **משוב** — "יפה!" או "נסה שוב"
- **כפתור "השמע שוב"** — מאפשר לתלמיד לבקש הקראה חוזרת

### מה צריך לממש

| הגדרה | תיאור |
|-------|--------|
| `voiceEnabled` | הגדרה (boolean) שמאפשרת למורה לכבות/להדליק הקראה |
| `autoSpeakOnNewRound` | האם להקריא אוטומטית בתחילת כל סיבוב |
| כפתור "השמע שוב" | כפתור נגיש שמאפשר הקראה חוזרת |

### ארכיטקטורת TTS

המערכת תומכת במספר ספקי TTS עם fallback אוטומטי:

```
Proxy TTS (ElevenLabs/Gemini)
  ↓ (אם נכשל)
Web Speech API (מובנה בדפדפן)
  ↓ (אם נכשל)
שקט (ללא הקראה)
```

### Cache

כדי לחסוך בקריאות API ולשפר ביצועים, מומלץ לשמור cache של הקלטות:
- **צד שרת** — R2/S3 בפרוקסי
- **צד לקוח** — IndexedDB בדפדפן

## 6. הגדרות חובה

כל משחק חייב לכלול את ההגדרות הבאות (מינימום):

### הגדרות ליבה

| הגדרה | סוג | תיאור |
|-------|------|--------|
| `boosterEnabled` | boolean | הפעלת/כיבוי מערכת המחזקים |
| `voiceEnabled` | boolean | הפעלת/כיבוי הקראה |
| `cooldownMs` | number | משך ההשהייה אחרי טעות (מילישניות) |

### הגדרות נפוצות נוספות

| הגדרה | סוג | תיאור |
|-------|------|--------|
| `gameMode` | enum | מצב משחק: "continuous" (רציף) או "manual_end" (סיום ידני) |
| רמת קושי | משתנה | פרמטרים שמשפיעים על הקושי (מספר אפשרויות, גודל לוח, וכו') |
| `shuffleX` | boolean | האם לערבב תוכן (אותיות, תמונות, וכו') |

## 7. שמירת הגדרות (Persistence)

### למה צריך

המורה מגדיר את ההגדרות פעם אחת, והן צריכות להישמר גם אחרי רענון הדף או סגירת הדפדפן.

### איך זה עובד

1. **שמירה ב-localStorage** — כל שינוי בהגדרות נשמר אוטומטית
2. **גרסת סכמה (schemaVersion)** — מספר שעולה כשמוסיפים הגדרות חדשות
3. **מיגרציה** — כשהגרסה השמורה ישנה מהגרסה הנוכחית, מתבצעת מיגרציה שמוסיפה את ההגדרות החדשות עם ברירות מחדל

### מבנה טיפוסי

```typescript
const STORAGE_KEY = "game-name-settings";
const CURRENT_VERSION = 3;

class SettingsStore {
  // הגדרות
  boosterEnabled = $state(true);
  voiceEnabled = $state(true);
  cooldownMs = $state(3000);
  
  constructor() {
    this.load();
    // שמירה אוטומטית בכל שינוי
    $effect(() => {
      this.save();
    });
  }
  
  private load() {
    const saved = localStorage.getItem(STORAGE_KEY);
    if (saved) {
      const parsed = JSON.parse(saved);
      this.migrate(parsed);
    }
  }
  
  private migrate(parsed: any) {

    if (version < 2) {

    }
  }
  
  reset() {

  }
}
```

## 8. עיצוב נגיש

### עקרונות מנחים

1. **Distraction-free** — ממשק נקי ללא אלמנטים מיותרים שמסיחים את הדעת
2. **אלמנטים גדולים** — כפתורים ואזורי לחיצה גדולים מספיק למגע (מינימום 70px)
3. **RTL מלא** — תמיכה מלאה בכיווניות מימין לשמאל
4. **משוב ברור** — חיווי ויזואלי וקולי מיידי לכל פעולה
5. **ניגודיות** — צבעים עם ניגודיות גבוהה לקריאות טובה

### גדלים מומלצים

| אלמנט | גודל מינימלי |
|-------|---------------|
| כפתור ראשי | 70px × 70px |
| כפתור משני | 48px × 48px |
| טקסט ראשי | 24px |
| רווח בין אלמנטים | לפחות 8px |

## 9. ניהול טקסטים

### כלל בסיסי

כל הטקסטים שמוצגים למשתמש (כותרות, כפתורים, הודעות) חייבים להיות מרוכזים בקובץ `language.ts`. חל איסור מוחלט על כתיבת מחרוזות בעברית ישירות בקומפוננטות.

### למה זה חשוב

1. **עקביות** — אותו טקסט מופיע זהה בכל מקום
2. **תחזוקה** — שינוי טקסט נעשה במקום אחד בלבד
3. **תרגום עתידי** — קל להוסיף שפות נוספות

### דוגמה

```typescript
// src/lib/services/language.ts
export const LANG = {
  buttons: {
    playAgain: "שחק שוב",
    speakAgain: "השמע שוב",
    newGame: "משחק חדש",
    settings: "הגדרות"
  },
  feedback: {
    correct: "יפה!",
    wrong: "נסה שוב",
    gameComplete: "כל הכבוד!"
  }
};

// בקומפוננטה
<button>{LANG.buttons.playAgain}</button>  // נכון
<button>שחק שוב</button>                   // אסור!
```

## 10. Debug והדפסות

### למה צריך

בזמן פיתוח ובדיקות, חשוב לדעת מה קורה בפנים — מה התשובה הנכונה, באיזה מצב המשחק, וכו'.

### מה להדפיס

- **בתחילת סיבוב** — התשובה הנכונה (לצורכי בדיקה)
- **בשינוי מצב** — המעבר בין מצבים
- **בשגיאות** — פרטי השגיאה

### דוגמה

```typescript
startRound() {
  // ...
  console.log(`[game-name] round ${this.roundNumber}: target = "${target}"`);
}
```

### הערה

הלוגים האלה עוזרים גם לבדיקות אוטומטיות וגם לדיבוג ידני. אפשר להשאיר אותם בקוד הייצור (הם לא מפריעים למשתמש).
